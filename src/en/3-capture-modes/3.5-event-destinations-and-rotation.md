# Output Destinations and Subscriptions

In v2.12.0, `--output` routes runtime logs and captured events. Without the flag, the destination is `stdout`. Explicit destinations **replace** that default. Repeat the flag once per destination to keep two copies.

```bash
sudo ecapture tls --model text --text-source pcapng \
  --output stdout --output capture.jsonl
```

## What each destination receives

| Destination | Text mode | Native keylog mode | Native pcapng mode |
| --- | --- | --- | --- |
| `--output stdout` or `stderr` | Labeled logs and decoded text | Logs and labeled NSS lines | Logs and labeled byte-count summaries |
| `--output PATH` or `file:///PATH` | Protobuf v2 JSON Lines, logs and `TEXT` events | JSON Lines, runtime logs only | JSON Lines, runtime logs only |
| `--output tcp://HOST:PORT` | Outgoing JSON Lines with logs and `TEXT` | Logs and `KEYLOG` bytes | Logs and `PCAPNG` bytes |
| `--stream-listen ws://HOST:PORT/PATH` | Incoming subscribers receive binary v2 logs/events | Binary v2 with `KEYLOG` bytes | Binary v2 with `PCAPNG` bytes |

Each terminal line identifies `log_type=log` or `log_type=event`, the module and, for an event, its capture format. In JSON Lines, read the `log_type` field of each v2 `LogEntry`. Its values for runtime logs and capture events are `LOG_TYPE_PROCESS_LOG` and `LOG_TYPE_EVENT`. Keep native artifact paths separate from `--output` files. [Output API](https://github.com/gojue/ecapture/blob/v2.12.0/docs/event-forward-api.md)

When running a development build after v2.12.0, the terminal output differs from the release described above. A native pcapng session prints only runtime logs. Multiline TEXT events have one prefix per event, and the SDK text header includes `pid` and `pname`. See [pcapng terminal changes](https://github.com/gojue/ecapture/commit/669a5f742d1f2cbe2d21a29f203764ceb90e27fa), [TEXT output changes](https://github.com/gojue/ecapture/commit/71e191ceb90bcfa2497a88e25c16f10044d4bbdc) and [eCaptureQ parser compatibility](/q/en/protocols/#raw).

## Subscribe to the collector

```bash
sudo ecapture tls --model text --text-source pcapng \
  --stream-listen ws://127.0.0.1:28256/
```

Connect to the configured path with a valid HTTP `Origin` header and the WebSocket subprotocol `ecapture.v2`. The Go receiver example uses `Origin: http://localhost/`. Each binary message contains one Protobuf v2 `LogEntry`. The first message is a heartbeat. The collector then sends its current `collector_info` snapshot when available, up to 128 recent runtime logs, and live events. The snapshot identifies the active module, mode and source, along with available host, build and destination information. The listener is disabled by default and supplies plain WS without built-in authentication. For eCaptureQ on the same host, enter `ws://127.0.0.1:28256/` as the source. [eCaptureQ quick start](/q/en/quick-start/) · [Wire format](https://github.com/gojue/ecapture/blob/v2.12.0/protobuf/PROTOCOLS.md) · [Receiver example](https://github.com/gojue/ecapture/blob/v2.12.0/examples/ecaptureq_client/README.md)

TCP output connects to an already-listening receiver. Buffer TCP data until a newline completes a JSON record. For a native `LOG_TYPE_EVENT`, read `event_payload.capture_format` and append the decoded bytes from `event_payload.keylog.data` or `event_payload.pcapng.data` in order. A ProtoJSON decoder already converts base64 byte fields to bytes. Record boundaries can divide an NSS line or pcapng block.

Starting a new capture generation on reload closes the connections. TCP reconnects, whereas WebSocket clients must resubscribe. Write a fresh receiver file per connection. A late pcapng subscriber gets headers and future packets and secrets only. TCP EOF alone does not confirm completion, so keep interrupted artifacts partial. The collector appends to its local native file across reloads. [Connection and completion rules](https://github.com/gojue/ecapture/blob/v2.12.0/docs/event-forward-api.md)

## Migrate v2.8–v2.11 commands

| Former option | v2.12.0 change |
| --- | --- |
| `--eventaddr`, `--logaddr`, `-l` | Repeat `--output` for terminal, file and TCP destinations. Update file/TCP readers to decode v2 JSON Lines. |
| Outgoing `ws://` or `wss://` outputs, `--ecaptureq` | Use a v2 WebSocket client connecting to `--stream-listen`, or a JSON Lines receiver for outgoing TCP. |
| `--listen` | Use `--config-listen HOST:PORT` to enable the separate HTTP configuration service. |
| `--eventroratesize`, `--eventroratetime` | Remove both flags. v2.12.0 has no CLI option for file rotation. |
| Implicit keylog/pcapng output or redirected stdout | Specify local `--keylogfile` or `--pcapfile` for the corresponding native mode. |

These legacy options have no aliases. Destinations and listener addresses are fixed at startup. Restart the collector to change them. [v2.12.0 migration details](https://github.com/gojue/ecapture/blob/v2.12.0/CHANGELOG.md)
