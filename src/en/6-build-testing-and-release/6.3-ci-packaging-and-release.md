# CI, Packaging, and Release

## Pull requests and capture tests

The upstream `GO/C/C++ CI` workflow builds on Ubuntu 22.04 amd64 and arm64, checks CO-RE and non-CO-RE builds, compiles cross-target variants, runs lint and executes `go test -v -race ./...`. CodeQL analyzes the Go and C/C++ sources separately. PR debug packaging uses Ubuntu 24.04 jobs and the same `TARGET_ARCH` initializer as the release workflow. Its tarballs preserve the executable inside the archive. [Build CI](https://github.com/gojue/ecapture/blob/v2.12.0/.github/workflows/go-c-cpp.yml) · [CodeQL](https://github.com/gojue/ecapture/blob/v2.12.0/.github/workflows/codeql-analysis.yml) · [Debug packages](https://github.com/gojue/ecapture/blob/v2.12.0/.github/workflows/pr_build_debug.yml)

The Linux capture matrix uses hosted Ubuntu 22.04 and 24.04 runners for OpenSSL, GoTLS and GnuTLS. Trusted changes also run OpenSSL and GoTLS CO-RE on a native Debian LoongArch64 runner. This job verifies the event commit and binary architecture, attaches probes to the real kernel, and cleans its capture files even on failure or cancellation. It retains the test log for seven days. Android runs its own Conscrypt/BoringSSL workload. See [TLS tests and E2E strategy](6.2-tls-test-and-e2e-strategy.md). [Linux E2E workflow](https://github.com/gojue/ecapture/blob/v2.12.0/.github/workflows/e2e.yml) · [Android E2E workflow](https://github.com/gojue/ecapture/blob/v2.12.0/.github/workflows/android_e2e.yml)

## What a release tag produces

A `v*` tag starts parallel Ubuntu 24.04 build jobs for `amd64`, `arm64` and `loong64`. Each selects its architecture with `TARGET_ARCH`, prepares the target headers and runs the release Makefile. Successful jobs upload validated artifacts for the publish job.

| Architecture | Expected files |
| --- | --- |
| amd64, arm64 | Linux tarball and Debian package, plus an Android tarball containing the executable. These packages are required before publishing. |
| loong64 | Linux tarball and Debian package. The build also audits the LoongArch toolchain and result. If this optional build fails, its files are omitted from that release. |

The publish job merges the uploaded artifacts, checks the required packages, generates the release checksums and publishes the GitHub Release. It then extracts the **same** amd64 and arm64 Linux executables from the published tarballs into the Docker build context. BuildKit selects the binary matching `TARGETARCH` for each image. Both architectures get the version tag, and stable releases also update `latest`.
