# TLS Test and E2E Strategy

## What each test verifies

Unit tests run decoders against short, padded and maximum-size samples and check module configuration and version mappings. On Linux, `go test -v -race ./...` checks the default-tag build. To exercise production code, generate actual bytecode with `make all` and use `make test-race`. The production-tag lint command also needs the target's built libpcap. [Build and test guide](https://github.com/gojue/ecapture/blob/v2.12.0/docs/agent/build-test.md)

The maintained Linux E2E harness runs on Ubuntu 22.04+ or Debian 13+ with root and an eBPF-capable kernel. It uses deterministic local clients and an independent Wireshark decoder. Install both `tshark` and `editcap` 4.4+ for the pcapng/QUIC checks, plus OpenSSL and GnuTLS development headers for the C workloads.

```sh
make all
sudo make e2e-linux
# Focus on the two GoTLS artifact modes.
sudo env E2E_MODULES=gotls E2E_MODES='keylog pcapng' bash test/e2e/run_e2e.sh
```

| Mode under test | Evidence required |
| --- | --- |
| Default text | The expected request or response appears while capture is running. The harness checks TLS 1.2 and 1.3 and independently decrypts the optional pcapng using embedded secrets. Hook-specific tests select `--text-source hook`. |
| Keylog | The local NSS file contains usable TLS 1.2 and 1.3 secrets that decrypt an independently collected packet capture. |
| Pcapng | The local file contains section/interface headers, packets and TLS Decryption Secrets Blocks. Decryption must work with its embedded secrets. |
| Output and reload | Each Linux core module exercises labeled stdout, JSON Lines file/TCP destinations, binary v2 subscriptions and same-probe HTTP reload. In native modes a file `--output` must contain only operational logs. |

## Protocol and platform coverage

GoTLS tests include segmented HTTP/1.1 and HTTP/2 bodies, HTTP/3 over QUIC v1/v2, raw binary TLS, DNS over TLS/HTTPS/QUIC and incremental SSE/gRPC. The HTTP/3 baseline checks two concurrent connections with two streams each and independently decrypts their bodies. It does not establish coverage of migration, 0-RTT or all QUIC states. OpenSSL checks bidirectional TLS 1.3 KeyUpdate, DTLS 1.2 ECDHE-RSA AES-GCM and connection reuse after `SSL_clear`. The GnuTLS keylog tests require both TLS versions to decrypt.

Android E2E uses a Linux host and a rooted API 33+ device/emulator. Its client uses platform Conscrypt/BoringSSL and sends a gated HTTPS request after the probe is ready. CI covers API 33–36. Native LoongArch E2E runs the OpenSSL and GoTLS CO-RE workloads on a dedicated Debian host. The non-core shell/database suite has separate entry points and its older output checks are outside the v2 transport gate.
