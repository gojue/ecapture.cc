# Other Modules

The release includes probes for NSPR I/O, interactive shells and SQL queries. These modules emit their own text events. The `--model` / `--text-source` combinations for the three core TLS modules do not apply here. The Linux build includes all five modules listed below. The Android build includes Bash alongside OpenSSL/BoringSSL and GoTLS. [Build and module matrix](https://github.com/gojue/ecapture/blob/v2.12.0/docs/agent/architecture.md)

## NSS and NSPR

`ecapture nspr` (alias `nss`) observes the data an application passes through `PR_Read` and `PR_Write`. The probe validates NSS 3.x and attaches to the library exporting those NSPR functions. It searches standard directories for `libnspr4.so`. Use `--nspr` to select an explicit library. NSPR produces read/write events. NSS key extraction and pcapng output belong to other workflows. [NSPR command](https://github.com/gojue/ecapture/blob/v2.12.0/cli/cmd/nss.go) · [NSPR probe](https://github.com/gojue/ecapture/blob/v2.12.0/internal/probe/nspr/nspr_probe.go)

## Bash and Zsh

| Command | Observable data | Configuration |
| --- | --- | --- |
| `bash` | Interactive Bash command lines collected through Readline. The probe also observes execution/exit hooks and can associate command completions with a status. | `--bash` selects the executable. If Readline lives in a shared library, supply both `--bash` and `--readlineso`. `--errnumber` omits completions with that status (default 128). |
| `zsh` | Interactive lines from Zsh's line editor. The probe observes a command before its exit status becomes available. | `--zsh` selects the executable. The accepted `--errnumber` option has no effect on Zsh output. |

The shell probes observe commands at different points. For a shell audit that needs the actual completion status, account for that difference before interpreting the output. [Bash command](https://github.com/gojue/ecapture/blob/v2.12.0/cli/cmd/bash.go) · [Zsh command](https://github.com/gojue/ecapture/blob/v2.12.0/cli/cmd/zsh.go)

## MySQL, MariaDB and PostgreSQL

`mysqld` observes SQL processed by the server's `dispatch_command`. Select the **server** executable with `--mysqld` (`-m`, default `/usr/sbin/mariadbd`). The server version and symbol layout affect target resolution. The module offers `--funcname` for an exact symbol and `--offset` for an existing file offset. The optional perf-reorder window can help order samples from different CPUs. [MySQL/MariaDB command](https://github.com/gojue/ecapture/blob/v2.12.0/cli/cmd/mysqld.go) · [Version and symbol resolution](https://github.com/gojue/ecapture/blob/v2.12.0/internal/probe/mysql/config.go)

`postgres` observes PostgreSQL 10+ simple-query execution in the server's `exec_simple_query` path. `--postgres` selects the **server binary**, and `--funcname` can select a function whose first argument contains the SQL string. Its scope is the simple-query protocol. When interpreting missing statements, first check which protocol the client used. [PostgreSQL command](https://github.com/gojue/ecapture/blob/v2.12.0/cli/cmd/postgres.go) · [PostgreSQL configuration](https://github.com/gojue/ecapture/blob/v2.12.0/internal/probe/postgres/config.go)

The maintained v2 output acceptance matrix focuses on `tls`, `gotls` and `gnutls`. The separate non-core shell/database tests still include legacy routing flags in v2.12.0. [Test coverage](https://github.com/gojue/ecapture/blob/v2.12.0/test/e2e/README.md)
