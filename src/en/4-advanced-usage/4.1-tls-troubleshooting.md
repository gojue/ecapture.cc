# TLS Troubleshooting

## The probe fails to start

Check the module's options with `ecapture tls --help` (also available for `gotls` and `gnutls`). Help runs without capture privileges. An unknown `--eventaddr`, `--logaddr` or `--ecaptureq` flag indicates a pre-v2.12 command. See [Integration and deployment](4.2-integration-and-deployment.md).

| Startup failure | What to check |
| --- | --- |
| Unsupported kernel or architecture | Linux requires x86_64 ≥ 4.18, arm64 ≥ 5.5 or loong64 ≥ 6.6. The Android build targets x86_64 and arm64. |
| Bytecode selection fails | With `--btf 0`, a non-CO-RE-only binary selects its embedded variant immediately. Other builds check kernel BTF, then select an available variant. CO-RE (`--btf 1`) needs usable BTF and a CO-RE object. An explicit non-CO-RE request (`--btf 2`) needs a non-CO-RE object. Check which variant your binary contains. |
| Permission error during load or TC attachment | Check the collector's eBPF/perf privileges. Both pcapng capture and the default pcapng-backed text source attach TC programs and require network administration privileges on the capture interface. |
| Library, ELF or symbol error | Confirm the program actually uses the selected library. Use `tls --libssl` for OpenSSL/BoringSSL, `gnutls --gnutls` for the GnuTLS library, and `gotls --elfpath` for the application executable. GoTLS attempts Go symbol-table recovery for stripped binaries. Verify the library layout and the reported symbol error before changing build flags. |

[Environment checks](https://github.com/gojue/ecapture/blob/v2.12.0/cli/cmd/env_detection.go) · [Bytecode selection](https://github.com/gojue/ecapture/blob/v2.12.0/internal/probe/bytecode/selector.go) · [GoTLS symbol resolution](https://github.com/gojue/ecapture/blob/v2.12.0/internal/probe/gotls/config_symbol.go)

## The probe starts, but there is no decoded request

1. **Check the interface.** In text mode the default `--text-source pcapng` needs both packets and secrets. The startup log identifies the selected interface and the reason for the choice. With no `-i`, selection prefers an up Ethernet interface on the lowest-metric default route, then traffic counters or another up interface. For a local loopback workload specify `-i lo`. A single selected interface may miss container or VPN traffic.
2. **Start a fresh test connection.** Start the collector before the handshake and generate one recognizable request from the application you are diagnosing. Check its PID filter and library or executable. A key log without matching packets, or packets without the corresponding secrets, cannot reconstruct the message.
3. **Inspect the optional capture.** In text mode set `--pcapfile sample.pcapng` to keep the same packets and embedded secrets seen by the decoder. Compare the request with [Wireshark](../3-capture-modes/3.6-wireshark-decryption-workflows.md). A pcapng file containing packets alone does not establish that eCapture observed the handshake secrets.
4. **Check the application protocol.** A custom binary protocol may produce no HTTP messages. For packet-backed text, `--text-raw` emits authenticated bytes. For long-running HTTP responses, `--text-http-events` exposes incremental events. `--text-source hook` selects the older, function-call-based representation for comparison and does not require a network interface.

The SDK reports rate-limited connection diagnostics for incomplete or unsupported traffic. Other connections can continue. An unexpected end to the live decoder is a terminal failure. eCapture reports it, releases the probe and exits nonzero. Check the process exit status and the last operational error. [Decryption and diagnostics](https://github.com/gojue/ecapture/blob/v2.12.0/docs/agent/output-pipeline.md)

## Output is missing or unreadable

| Symptom | Explanation and remedy |
| --- | --- |
| Text disappeared from the terminal after adding a file | An explicit destination replaces the default stdout. Use `--output stdout --output capture.jsonl` to keep both. |
| The output file contains JSON or only runtime logs | A file destination receives JSON Lines. In `keylog` or `pcapng` mode it receives only runtime logs. Specify a separate local `--keylogfile` or `--pcapfile` for the native artifact. Check write permissions and free space for both paths. |
| A WebSocket client cannot connect | Enable `--stream-listen`, connect to its configured path, and negotiate `ecapture.v2`. Non-browser clients also send a valid Origin. See [the receiver example](https://github.com/gojue/ecapture/blob/v2.12.0/examples/ecaptureq_client/README.md). |
| A new subscriber cannot decrypt an existing connection | The server sends current section headers and future packets and secrets. Subscribe before opening the test connection. After reload, reconnect and save to a fresh receiver file. |
