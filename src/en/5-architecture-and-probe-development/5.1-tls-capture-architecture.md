# TLS Capture Architecture

## From attachment to capture

The CLI creates a concrete probe through the factory. Each module chooses its library or binary and sets up an eBPF manager with matching attachments, maps and decoders. `BaseProbe` supplies tracked readers and dispatch. The capture mode **and** text source determine which records the manager needs.

| Mode / source | Collected records | Result |
| --- | --- | --- |
| `text` with `pcapng` (default) | TC packets on the selected interface and TLS secret events from the target | A live pcapng stream feeds the decryption SDK. It emits reconstructed messages or explicitly selected protocol events. |
| `text` with `hook` | TLS read/write function events | Individual plaintext reads/writes through the compatibility path. |
| `keylog` | TLS secret events | Deduplicated NSS key log lines. |
| `pcapng` | TC packets and TLS secret events | Packets and Decryption Secrets Blocks in a pcapng file. |

The gradual deprecation applies to hook-based **plaintext**. The default packet-backed text path still consumes secret events produced by the library/runtime probes. ## Library and symbol resolution

- **OpenSSL/BoringSSL.** The `tls` module selects eBPF objects with offsets for the detected library version. Its private connection records enrich applicable data events before dispatch. Secret capture rejects incomplete OpenSSL snapshots when the client random has not yet been initialized, including session reuse after `SSL_clear`. [OpenSSL implementation](https://github.com/gojue/ecapture/blob/v2.12.0/internal/probe/openssl/openssl_probe.go) · [Release history](https://github.com/gojue/ecapture/blob/v2.12.0/CHANGELOG.md)
- **Go TLS.** The probe resolves functions in the selected executable, handles Go's stack and register calling conventions and uses Go symbol data when ELF symbols are missing. The selected mode determines whether it needs plaintext read/write or secret-writing sites. [GoTLS symbol resolution](https://github.com/gojue/ecapture/blob/v2.12.0/internal/probe/gotls/config_symbol.go) · [GoTLS implementation](https://github.com/gojue/ecapture/blob/v2.12.0/internal/probe/gotls/gotls_probe.go)
- **GnuTLS.** The detected version selects a measured object layout. The mapping includes 3.8.10 and reuses the 3.8.11 object for upstream 3.8.12 and 3.8.13. The version check runs before attachment. [GnuTLS configuration and asset map](https://github.com/gojue/ecapture/blob/v2.12.0/internal/probe/gnutls/config.go)

## The C/Go boundary

Kernel event records are a binary ABI. The reader chooses a module decoder by eBPF map. Field order, signedness, widths, padding and byte order must agree between C and Go. For example, the GoTLS **hook** event `go_tls_event` is decoded little-endian.

| Wire offset | Contents |
| --- | --- |
| 0–15 | 64-bit monotonic timestamp, then 32-bit PID and TID |
| 16–27 | Signed 32-bit data length, one-byte event type, three padding bytes and a 32-bit file descriptor |
| 28–67 | Source and destination addresses (16 bytes each), ports, IP version and alignment bytes |
| 68–83 | 16-byte process name |
| 84 onward | Payload. The decoder checks the declared length against both remaining bytes and the 16 KiB limit. |

Packet-mode events have a different ABI. The TC event carries process identity and, when available, a bounded argument snapshot. The pcapng writer preserves endpoint attribution with the packet and stores argv in an Enhanced Packet Block comment. Downstream decoded events can then retain PID, process name and up to 256 bytes of arguments with an explicit truncation flag. Unknown ownership stays unknown.
