# GnuTLS Capture

`gnutls` (alias `gnu`) observes applications linked to GnuTLS on Linux. The collector locates `libgnutls.so.30` in common system directories. Pass `--gnutls /path/to/libgnutls.so.30` when the target loads a different copy.

## Match the library patch version

GnuTLS handshake structures have version-specific layouts. eCapture reads the version from the library image. If you know the installed patch version, `--ssl_version 3.8.12`, for example, supplies it explicitly. v2.10.0 added measured layouts for GnuTLS 3.8.10–3.8.13. Match the installed patch to the bytecode layout used by v2.12.0.

| Patch range | Bytecode layout selected |
| --- | --- |
| 3.6.12 / 3.6.13–3.6.16 | 3.6.12 / 3.6.13 |
| 3.7.0–3.7.2 / 3.7.3–3.7.6 / 3.7.7–3.7.11 | 3.7.0 / 3.7.3 / 3.7.7 |
| 3.8.0–3.8.3 / 3.8.4–3.8.6 / 3.8.7–3.8.9 | 3.7.7 / 3.8.4 / 3.8.7 |
| 3.8.10 / 3.8.11–3.8.13 | 3.8.10 / 3.8.11 |

The validator rejects versions outside the mapping. A SONAME such as `libgnutls.so.30` can remain the same across many patch versions. Use the actual patch level when checking support. [Full GnuTLS version map](https://github.com/gojue/ecapture/blob/v2.12.0/internal/probe/gnutls/config.go) · [Release notes](https://github.com/gojue/ecapture/blob/v2.12.0/CHANGELOG.md)

## Capture and verify

```bash
sudo ecapture gnutls --model text --text-source pcapng
sudo ecapture gnutls --model keylog --keylogfile gnutls.keys
sudo ecapture gnutls --model pcapng --pcapfile gnutls.pcapng
```

Choose one command, then open a new connection from a GnuTLS-backed test client. For decoded text, confirm a known request path or response body. For keylog, match the keys against a separate capture of the same connection. For pcapng, open the native file in Wireshark and check that the expected application data decrypts. Set `-i lo` for a client and server communicating over loopback. [Wireshark verification](../3-capture-modes/3.6-wireshark-decryption-workflows.md)

## Handshake and record events

Packet-based text, native keylog and native pcapng obtain secrets at `gnutls_handshake` using the selected layout. A native pcapng file carries these secrets in Decryption Secrets Blocks alongside packet blocks. The default text path streams these blocks to the SDK and emits decoded messages. Explicit `--text-source hook` uses `gnutls_record_recv` and `gnutls_record_send` to deliver chunks from record I/O. [GnuTLS capture implementation](https://github.com/gojue/ecapture/blob/v2.12.0/internal/probe/gnutls/gnutls_probe.go)
