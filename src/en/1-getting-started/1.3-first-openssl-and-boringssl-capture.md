## Purpose and Scope

This page provides a verified end-to-end walkthrough for capturing TLS plaintext events from OpenSSL and BoringSSL shared libraries using `ecapture` in text mode. It covers command execution, traffic generation, expected output structure, and references to advanced keylog and pcapng workflows.

## Prerequisites and Environment Setup

Before running your first OpenSSL capture, verify that your environment meets the core requirements:
- **Operating System & Kernel**: Linux kernel version 4.18 or higher with BTF (BPF Type Format) support enabled.
- **Privileges**: Root access (or `CAP_SYS_ADMIN` / `CAP_BPF` capabilities) is required to load eBPF programs and attach uprobes.
- **Target Application**: A dynamic binary or service linked against OpenSSL (`libssl.so.1.1`, `libssl.so.3`) or BoringSSL (`libssl.so` on Android or embedded environments).

## Verified End-to-End Text-Mode Command

By default, `ecapture tls` operates in text mode (`-m text`), intercepting `SSL_read` and `SSL_write` function calls to decode and print plaintext HTTP or application payloads to standard output.

### 1. Launching eCapture

Run the following command with root privileges, specifying the target OpenSSL/BoringSSL library path if necessary, or letting `ecapture` auto-detect it:

```bash
sudo ./bin/ecapture tls -m text
```

If targeting a specific library path or interface (particularly on Android / BoringSSL environments), supply the explicit path flag:

```bash
sudo ./bin/ecapture tls -m text --libssl /usr/lib/x86_64-linux-gnu/libssl.so.3
```

## Links to Advanced Workflows

Once you have verified text-mode capture, you can transition to other operational modes depending on your analysis requirements:
- **Keylog Mode**: Export NSS key log lines to disk for external packet analyzers using `-m keylog` (see Section 3.3).
- **pcapng Mode**: Capture network packets with embedded TLS Decryption Secrets Blocks using `-m pcap` or `-m pcapng` (see Section 3.4).
