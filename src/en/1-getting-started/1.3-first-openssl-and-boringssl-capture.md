# First OpenSSL and BoringSSL Capture

Use an HTTPS client linked to OpenSSL or BoringSSL and a test endpoint you control. On Linux, check the client with `curl -V`. If it reports GnuTLS, follow the [GnuTLS example](1.5-first-gnutls-capture.md) for that client.

## Start the collector, then make a request

```bash
sudo ecapture tls --model text --text-source pcapng
```

The collector searches standard locations for `libssl` and logs the interface it chose. If several OpenSSL builds are installed, pass `--libssl` with the library path used by the client. On Android, use the Android executable and the device's BoringSSL library. The next example selects loopback for a local test server on port 8443.

```bash
sudo ecapture tls --model text --text-source pcapng -i lo 'tcp port 8443'
```

In a second terminal, make a new HTTPS connection with a distinctive request path. This example assumes the local test server has a certificate trusted by curl and valid for `localhost`.

```bash
curl --http1.1 https://localhost:8443/ecapture-check
```

## Recognize a decoded message

The probe supplies secrets from your client or server's matching TLS library. The packet capture supplies bytes from the selected interface. eCapture matches them and decodes the HTTP request and response. The terminal event for this test would contain the requested path.

```text
[log_type=event capture_format=text module=tls] GET /ecapture-check HTTP/1.1\x0d
```

Runtime diagnostics have `log_type=log`. If you see only startup logs, check the TLS backend and the interface named in those logs, then open a **new** connection after eCapture is ready. Use `Ctrl+C` to stop. To inspect the same packets later, add `--pcapfile session.pcapng` to the collector command.
