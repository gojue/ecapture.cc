# Requirements and Installation

## Check the capture host

Run `uname -m` and `uname -r` on the host or device where the application runs. The collector uses Linux kernel facilities for uprobes and packet capture.

| Release architecture | Kernel minimum | Collector targets |
| --- | --- | --- |
| `amd64` (`x86_64`) | 4.18 | Linux and Android |
| `arm64` (`aarch64`) | 5.5 | Linux and Android |
| `loong64` (`loongarch64`) | 6.6 | Linux |

Linux includes all three TLS modules. Android packages provide `tls` for OpenSSL/BoringSSL and `gotls` for Go TLS applications. [Supported platforms and modules](https://github.com/gojue/ecapture/blob/v2.12.0/README.md)

## Install a release

Choose the package for your operating system and CPU on the [download page](/en/download/). For example, download the Linux amd64 archive and `checksum-v2.12.0.txt` into the same directory. Check that `sha256sum` prints `OK` for the selected archive before running `tar`.

```bash
sha256sum --check --ignore-missing checksum-v2.12.0.txt &&
  tar -xzf ecapture-v2.12.0-linux-amd64.tar.gz
```

In the extracted directory, run `./ecapture --version` and `./ecapture tls --help`. Run subsequent examples with `./ecapture` there, or use `ecapture` after installing it on your `PATH`. Android archives include a device executable. [Package verification](https://github.com/gojue/ecapture/blob/v2.12.0/docs/release-verification.md)

## Kernel features and privileges

The kernel needs eBPF and uprobe support. CO-RE bytecode uses kernel BTF, normally exposed at `/sys/kernel/btf/vmlinux`. Non-CO-RE bytecode must match the target kernel and be available in the build. A source build on Linux requires Go, Clang/LLVM and the project submodules. Loong64 release builds use LLVM 22.1.8. See [building and selecting bytecode assets](../6-build-testing-and-release/6.1-build-and-bytecode-assets.md) for build targets. [Build requirements](https://github.com/gojue/ecapture/blob/v2.12.0/docs/compilation.md)

The capture examples use `sudo`. If you assign capabilities instead, distinguish probes that also attach Traffic Control (TC) programs to a network interface.

| Capture path | Linux 5.8 or later | Earlier supported kernels |
| --- | --- | --- |
| Keylog or explicit `--text-source hook` | `CAP_BPF`, `CAP_PERFMON`, `CAP_SYS_PTRACE` | `CAP_SYS_ADMIN` |
| Native pcapng or default packet-based text | Same capabilities plus `CAP_NET_ADMIN` for TC attachment | `CAP_SYS_ADMIN`, `CAP_NET_ADMIN` |

The default text path and pcapng mode require an active interface carrying the test traffic. Startup logs name the selected interface. Use `-i lo` for a local loopback test, or select the interface in the workload's network namespace. Keep the target library or Go ELF reachable by the collector. [Linux capabilities](https://github.com/gojue/ecapture/blob/v2.12.0/docs/minimum-privileges.md) · [Interface selection](https://github.com/gojue/ecapture/blob/v2.12.0/internal/config/capture_interface.go)
