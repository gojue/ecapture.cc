# Choosing a TLS Probe

Choose the module by the TLS implementation **inside the application making the connection**. A service written in Go can talk to a client built with GnuTLS. Either endpoint can supply secrets for the same session if its probe supports that implementation.

| Evidence from the application | Module | Target to identify | First capture |
| --- | --- | --- | --- |
| OpenSSL or BoringSSL, including Android's system BoringSSL | `tls` (alias `openssl`) | Actual `libssl` shared object, optionally set with `--libssl` | [OpenSSL/BoringSSL example](1.3-first-openssl-and-boringssl-capture.md) |
| Go executable uses the standard library's `crypto/tls` | `gotls` (alias `tlsgo`) | The exact executable, required via `--elfpath` | [Go example](1.4-first-gotls-capture.md) |
| Linux application loads `libgnutls.so` | `gnutls` (alias `gnu`) | Actual GnuTLS shared object, optionally set with `--gnutls` | [GnuTLS example](1.5-first-gnutls-capture.md) |

## Confirm before capturing

- For a curl-based test, `curl -V` reports its TLS backend. Run the check on the capture host, since the developer's copy may use a different backend.
- For a Go service you build, check its metadata with `go version -m /path/to/service` and confirm that the code path under test uses `crypto/tls`. A cgo library can use another TLS implementation.
- When several library versions are installed, select the one loaded by the test application. A matching filename from a different image or installation can refer to another file.

All three modules default to `--model text --text-source pcapng`. Independently choose the interface carrying the packets. If a local service listens on loopback, pass `-i lo`. See [choosing an output mode](../3-capture-modes/3.1-choosing-text-keylog-or-pcapng.md) for saved packets or standalone secrets.
