# 初探 OpenSSL 与 BoringSSL 捕获

选择链接 OpenSSL 或 BoringSSL 的 HTTPS 客户端，访问自己的测试服务。在 Linux 上可用 `curl -V` 确认客户端后端。如果显示 GnuTLS，请使用[GnuTLS 入门示例](1.5-first-gnutls-capture.md)。

## 先启动采集器，再发起请求

```bash
sudo ecapture tls --model text --text-source pcapng
```

采集器会在标准路径查找 `libssl`，并在日志中显示选中的网卡。若安装了多个 OpenSSL 版本，可以通过 `--libssl` 指定客户端实际加载的库。在 Android 上使用 Android 可执行文件及设备中的 BoringSSL 库。下面的命令使用回环网卡采集本机测试服务 8443 端口的流量。

```bash
sudo ecapture tls --model text --text-source pcapng -i lo 'tcp port 8443'
```

在另一个终端中，新建 HTTPS 连接并请求一个容易识别的路径。以下示例假设本机测试服务的证书对 `localhost` 有效，且 curl 已信任其签发机构。

```bash
curl --http1.1 https://localhost:8443/ecapture-check
```

## 识别解码后的消息

探针从客户端或服务端所用的 TLS 库获取密钥，网卡采集提供数据包。eCapture 将两者匹配后解码 HTTP 请求和响应。例如，该测试请求的终端事件中会带有请求路径。

```text
[log_type=event capture_format=text module=tls] GET /ecapture-check HTTP/1.1\x0d
```

运行日志的标识是 `log_type=log`。如果只有启动日志，检查客户端 TLS 后端和日志中显示的网卡，等 eCapture 就绪后**新建连接**重试。使用 `Ctrl+C` 停止采集。若还需离线查看本次数据包，可在采集命令中增加 `--pcapfile session.pcapng`。详见 [TLS 库选择](../2-core-tls-modules/2.1-tls-capture-openssl-and-boringssl.md)和[文本输出](../3-capture-modes/3.2-text-mode.md)。[终端输出格式](https://github.com/gojue/ecapture/blob/v2.12.0/docs/example-outputs.md)
