# 初探 GnuTLS 捕获

在 Linux 上选择链接到受支持版本 `libgnutls.so` 的应用。例如使用 `curl -V` 输出中标有 GnuTLS 的 curl。Android 采集器未包含 `gnutls` 命令。

## 采集一次 HTTPS 事务

```bash
sudo ecapture gnutls --model text --text-source pcapng
```

采集器搜索常用库路径，识别补丁版本后选择与之匹配的数据结构布局。若程序使用私有安装目录，可通过 `--gnutls /path/to/libgnutls.so.30` 指定实际加载的库。检查启动日志中的网卡，本地回环流量使用 `-i lo`。

保持 eCapture 运行，用 GnuTLS 客户端向自己的 HTTPS 测试服务器请求一个已知路径。新建连接以便采集握手。终端将解码记录标为 `log_type=event` 和 `module=gnutls`。找到请求路径及其响应，才能确认对应事务已经解密。仅看到握手日志或文件增长还不够。

## 为 Wireshark 保留抓包

```bash
sudo ecapture gnutls --model pcapng --pcapfile gnutls.pcapng
```

采集期间再次发起请求，使用 `Ctrl+C` 停止采集，再用 Wireshark 打开文件。如果已有独立的网络抓包流程，可在同一次连接期间改用 `--model keylog --keylogfile gnutls.keys` 收集密钥。参见[支持的补丁版本列表](../2-core-tls-modules/2.3-gnutls-capture.md)和[解密验证方法](../3-capture-modes/3.6-wireshark-decryption-workflows.md)。[GnuTLS 命令](https://github.com/gojue/ecapture/blob/v2.12.0/cli/cmd/gnutls.go) · [库检测逻辑](https://github.com/gojue/ecapture/blob/v2.12.0/internal/probe/gnutls/config.go)
