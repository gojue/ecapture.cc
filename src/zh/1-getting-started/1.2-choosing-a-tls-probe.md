# 选择 TLS 探针

根据**建立 TLS 连接的应用实际使用的 TLS 实现**选择探针。例如 Go 服务可以处理 GnuTLS 客户端发来的请求。只要探针支持对应的实现，在任一端获取的密钥都可以用于该会话。

| 应用特征 | 模块 | 需要确认的目标 | 首次采集 |
| --- | --- | --- | --- |
| OpenSSL 或 BoringSSL，包括 Android 系统 BoringSSL | `tls`（别名 `openssl`） | 应用实际使用的 `libssl` 共享库，可通过 `--libssl` 指定 | [OpenSSL/BoringSSL 示例](1.3-first-openssl-and-boringssl-capture.md) |
| Go 可执行文件使用标准库 `crypto/tls` | `gotls`（别名 `tlsgo`） | 通过必填的 `--elfpath` 指定目标可执行文件 | [Go 示例](1.4-first-gotls-capture.md) |
| Linux 应用加载 `libgnutls.so` | `gnutls`（别名 `gnu`） | 实际加载的 GnuTLS 共享库，可通过 `--gnutls` 指定 | [GnuTLS 示例](1.5-first-gnutls-capture.md) |

## 采集前确认

- 用 curl 做测试时，`curl -V` 会显示其 TLS 后端。请在采集主机上检查，开发机上的 curl 可能使用不同的 TLS 库。
- 对于自行构建的 Go 服务，可以用 `go version -m /path/to/service` 检查构建信息，再确认测试代码路径使用 `crypto/tls`。通过 cgo 调用的库可能使用其他 TLS 实现。
- 如果安装了多个版本的库，请指定测试应用实际加载的文件。另一个容器镜像或安装目录中可能存在同名但不同的库。

三个模块都默认使用 `--model text --text-source pcapng`。还需要单独确认承载数据包的网卡，例如本地回环服务使用 `-i lo`。如果需要保留密钥或数据包，参见[捕获模式选择](../3-capture-modes/3.1-choosing-text-keylog-or-pcapng.md)。[TLS 命令](https://github.com/gojue/ecapture/blob/v2.12.0/cli/cmd/tls.go) · [GoTLS 命令](https://github.com/gojue/ecapture/blob/v2.12.0/cli/cmd/gotls.go) · [GnuTLS 命令](https://github.com/gojue/ecapture/blob/v2.12.0/cli/cmd/gnutls.go)
