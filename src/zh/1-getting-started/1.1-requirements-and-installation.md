# 环境要求与安装

## 检查采集主机

在运行应用的主机或设备上执行 `uname -m` 和 `uname -r`。采集器依赖 Linux 内核的 uprobe 与网络抓包能力。

| 发布包架构 | 最低内核 | 采集平台 |
| --- | --- | --- |
| `amd64`（`x86_64`） | 4.18 | Linux、Android |
| `arm64`（`aarch64`） | 5.5 | Linux、Android |
| `loong64`（`loongarch64`） | 6.6 | Linux |

Linux 版本包含全部三个 TLS 模块。Android 包提供用于 OpenSSL/BoringSSL 的 `tls` 和用于 Go TLS 程序的 `gotls`。[平台与模块支持列表](https://github.com/gojue/ecapture/blob/v2.12.0/README.md)

## 安装发布包

从[下载页](/zh/download/)选择与操作系统、CPU 匹配的包。例如，将 Linux amd64 压缩包和 `checksum-v2.12.0.txt` 下载至同一目录，在执行 `tar` 前，先确认 `sha256sum` 对所选包输出 `OK`。

```bash
sha256sum --check --ignore-missing checksum-v2.12.0.txt &&
  tar -xzf ecapture-v2.12.0-linux-amd64.tar.gz
```

在解压后的目录中运行 `./ecapture --version` 和 `./ecapture tls --help`。后续示例可在该目录使用 `./ecapture`，或将可执行文件安装到 `PATH` 后使用 `ecapture`。Android 压缩包包含可在设备上运行的程序。[发布包校验说明](https://github.com/gojue/ecapture/blob/v2.12.0/docs/release-verification.md)

## 内核特性与权限

内核需支持 eBPF 和 uprobe。CO-RE 字节码使用内核 BTF，通常可在 `/sys/kernel/btf/vmlinux` 找到。使用非 CO-RE 字节码时，构建产物中需要包含与目标内核匹配的对象文件。在 Linux 上从源码构建还需 Go、Clang/LLVM 及项目子模块。Loong64 发布包使用 LLVM 22.1.8。各编译目标见[构建与字节码资源](../6-build-testing-and-release/6.1-build-and-bytecode-assets.md)。[上游编译说明](https://github.com/gojue/ecapture/blob/v2.12.0/docs/compilation.md)

教程使用 `sudo` 运行采集。如果采用 Linux capabilities 单独授权，需要区分采集方式是否在网卡上挂载流量控制（TC）程序。

| 采集路径 | Linux 5.8 及以上 | 更早的受支持内核 |
| --- | --- | --- |
| 密钥日志或显式 `--text-source hook` | `CAP_BPF`、`CAP_PERFMON`、`CAP_SYS_PTRACE` | `CAP_SYS_ADMIN` |
| 原生 pcapng 或默认的网络包文本解密 | 同上，另需挂载 TC 所用的 `CAP_NET_ADMIN` | `CAP_SYS_ADMIN`、`CAP_NET_ADMIN` |

默认文本模式和 pcapng 模式均需要一张承载测试流量的活动网卡。启动日志会显示选中的网卡。本地回环测试指定 `-i lo`，容器内流量要选用工作负载所在网络命名空间的网卡。采集器还须能够访问目标程序使用的库或 Go ELF 文件。[Linux 权限要求](https://github.com/gojue/ecapture/blob/v2.12.0/docs/minimum-privileges.md) · [网卡选择逻辑](https://github.com/gojue/ecapture/blob/v2.12.0/internal/config/capture_interface.go)
