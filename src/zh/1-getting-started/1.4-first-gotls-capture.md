# 初探 GoTLS 捕获

选择自己构建、通过 `crypto/tls` 发起或接受 HTTPS 连接的 Go 客户端或服务端，准备一个路径容易识别的请求。采集器需要访问运行中应用使用的同一份 ELF 可执行文件，其他构建产物的函数地址可能不同。

## 选择目标程序和网卡

```bash
sudo ecapture gotls --elfpath ./go-client --model text --text-source pcapng
```

将 `./go-client` 替换为实际程序路径。PID 筛选可以缩小采集范围，`--elfpath` 仍然必填。默认文本数据源将程序提供的 TLS 密钥与所选网卡上的数据包配对。若客户端访问回环地址上的服务，指定 `-i lo`。要在查看终端的同时保留解码记录，可追加 `--output stdout --output go.jsonl`。[GoTLS 命令参数](https://github.com/gojue/ecapture/blob/v2.12.0/cli/cmd/gotls.go)

## 用测试请求验证

1. 等待探针启动，在另一个终端运行所选客户端，或向所选 Go 服务发起 HTTPS 请求，建立新连接。
2. 查找带有请求路径的 `event` 记录和同一连接上的响应。如果 HTTP/2 在一条连接上复用多个请求，用流 ID 匹配每一对请求和响应。
3. 如果没有对应的消息，检查目标可执行文件和启动日志中显示的网卡。如果测试 QUIC，请确认抓包条件包含 UDP 流量。

如需独立核验解密结果，在同一文本采集命令中加入 `--pcapfile go.pcapng`，然后按 [Wireshark 工作流](../3-capture-modes/3.6-wireshark-decryption-workflows.md)查看。要在迁移期间检查单次函数读写片段，可指定 `--text-source hook`。符号解析和其他模式见 [GoTLS 捕获](../2-core-tls-modules/2.2-gotls-capture.md)。[输出示例](https://github.com/gojue/ecapture/blob/v2.12.0/docs/example-outputs.md)
