# CI、打包与发布

## PR 构建与捕获测试

上游的 `GO/C/C++ CI` 工作流在 Ubuntu 22.04 amd64 和 arm64 上编译 CO-RE、非 CO-RE 和交叉目标，执行 lint 及 `go test -v -race ./...`。CodeQL 分别分析 Go 与 C/C++ 源码。PR 调试包另用 Ubuntu 24.04 的矩阵任务，和正式发布共用 `TARGET_ARCH` 初始化入口。归档以 tarball 形式保留可执行文件权限。[构建 CI](https://github.com/gojue/ecapture/blob/v2.12.0/.github/workflows/go-c-cpp.yml) · [CodeQL](https://github.com/gojue/ecapture/blob/v2.12.0/.github/workflows/codeql-analysis.yml) · [PR 调试包](https://github.com/gojue/ecapture/blob/v2.12.0/.github/workflows/pr_build_debug.yml)

Linux 捕获矩阵在托管的 Ubuntu 22.04 和 24.04 上验证 OpenSSL、GoTLS、GnuTLS。受信任变更还会在原生 Debian LoongArch64 运行器执行 OpenSSL 和 GoTLS 的 CO-RE 用例。该任务核对触发任务的提交和二进制架构，在真实内核上挂载探针，成功、失败或取消时均清理捕获文件，测试日志保留七天。Android 运行独立的 Conscrypt/BoringSSL 工作负载。参见 [TLS 测试与端到端策略](6.2-tls-test-and-e2e-strategy.md)。[Linux 端到端工作流](https://github.com/gojue/ecapture/blob/v2.12.0/.github/workflows/e2e.yml) · [Android 端到端工作流](https://github.com/gojue/ecapture/blob/v2.12.0/.github/workflows/android_e2e.yml)

## 发布标签会生成什么

`v*` 标签触发 Ubuntu 24.04 上三个并行构建任务，分别为 `amd64`、`arm64`、`loong64`。各任务用 `TARGET_ARCH` 选择架构、准备目标头文件并运行发布 Makefile，再将验证通过的产物上传给发布任务。

| 架构 | 预期文件 |
| --- | --- |
| amd64、arm64 | Linux tarball、Debian 包，还有包含可执行文件的 Android tarball。发布前必须验证这些产物齐全。 |
| loong64 | Linux tarball 和 Debian 包。任务还审查 LoongArch 工具链和产物。如果此可选构建失败，当次发布不含该架构的包。 |

发布任务合并各架构产物，检查必需的软件包，生成校验和并发布 GitHub Release。随后从已发布的 amd64、arm64 Linux tarball 中提取**同一份**可执行文件，放入 Docker 构建上下文。BuildKit 按 `TARGETARCH` 为每个平台复制相应文件。两种架构均带版本标签，稳定版还会更新 `latest`。[发布工作流](https://github.com/gojue/ecapture/blob/v2.12.0/.github/workflows/release.yml) · [发布 Makefile](https://github.com/gojue/ecapture/blob/v2.12.0/builder/Makefile.release) · [容器构建文件](https://github.com/gojue/ecapture/blob/v2.12.0/builder/Dockerfile)
