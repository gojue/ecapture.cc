# 编译构建与字节码资产

## 构建主机与目标架构

采集器须在 Linux 环境编译，Android 程序也在 Linux 主机上构建。v2.12.0 需要 Go 1.26.0 或更新版本、GNU Make、C 工具链、Clang/LLVM、bpftool、内核头文件和递归检出的 `lib/libpcap` 子模块。在上游采集器仓库运行 `bash builder/init_env.sh` 可准备环境，随后应用脚本打印的环境变量。`TARGET_ARCH` 用于选择产物架构，省略时默认选择本机。仅在未设置 `TARGET_ARCH` 时，兼容参数 `CROSS_ARCH` 才会参与选择。

| 目标 | 项目使用的工具链与环境 | 运行平台 |
| --- | --- | --- |
| `amd64`、`arm64` | 发布和 PR 打包统一使用 Ubuntu 24.04，BPF 编译使用 LLVM 14，同时使用匹配的原生或交叉 C 工具链。 | Linux 和 Android。x86_64 最低内核 4.18，arm64 最低 5.5。 |
| `loong64` | 可在 Ubuntu 24.04 x86_64 上交叉编译，或在 Debian 13+ 上原生编译。两者均使用 LLVM/Clang/LLD 22.1.8 和配套的 LoongArch64 LP64D 目标工具链及库。 | Linux loongarch64，内核 6.6+。 |

交叉编译要准备**目标架构**的内核头文件与配置，并让 `KERN_HEADERS` 指向该目录。本机非 CO-RE 构建通常使用当前内核的 build/source 目录。生成 LoongArch CO-RE 的 `vmlinux.h` 则需要目标 BTF。[编译说明](https://github.com/gojue/ecapture/blob/v2.12.0/docs/compilation-zh_Hans.md) · [架构选择逻辑](https://github.com/gojue/ecapture/blob/v2.12.0/variables.mk) · [LoongArch 构建细节](https://github.com/gojue/ecapture/blob/v2.12.0/docs/loong64-support.md)

## 从 C 对象到可执行文件

```text
kern/*.c
  -> .build/<target>-<goarch>/bytecode/*_kern_{core,noncore}.o
  -> assets/ebpf_probe_<target>_<goarch>_bindata.go
  -> .build/<target>-<goarch>/bin/ecapture
  -> bin/ecapture
```

`make core` 只内嵌 CO-RE 对象，`make nocore` 只内嵌非 CO-RE 对象，`make all` 同时内嵌两类。CO-RE 利用类型信息重定位，非 CO-RE 则根据已准备的内核头文件编译，其编译参数已处理 Linux 6.19+ 匿名字段和 Linux 7.x x86 头文件的兼容问题。两种构建都会用 `llvm-strip -g` 清理 DWARF 并保留 BTF。运行时的选择器会检查二进制是否含有所需的字节码。[字节码生成规则](https://github.com/gojue/ecapture/blob/v2.12.0/Makefile) · [运行时选择器](https://github.com/gojue/ecapture/blob/v2.12.0/internal/probe/bytecode/selector.go)

构建环境就绪后，在 Linux 源码目录执行以下命令。

```sh
git submodule update --init --recursive
make clean
make env
make all
file bin/ecapture
```

Makefile 为目标架构构建 libpcap 并通过 CGO 链接。`ebpfassets` 构建选用生成的字节码资产，`ecap_android` 选择 Android 模块集。直接用 Go 构建可能选中不含实际探针对象的占位文件。链接阶段会验证可执行文件为静态 PIE、没有 ELF 解释器及共享库依赖，之后再复制到 `bin/ecapture`。[Go 构建与链接检查](https://github.com/gojue/ecapture/blob/v2.12.0/functions.mk) · [构建标签与验证](https://github.com/gojue/ecapture/blob/v2.12.0/docs/agent/build-test.md)
