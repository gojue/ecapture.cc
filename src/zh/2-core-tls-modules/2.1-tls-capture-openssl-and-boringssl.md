# TLS 捕获 (OpenSSL/BoringSSL)

`tls`（别名 `openssl`）面向应用实际加载的 OpenSSL 或 BoringSSL 库。首次 HTTPS 请求及其终端输出示例见[初探 OpenSSL 与 BoringSSL 捕获](../1-getting-started/1.3-first-openssl-and-boringssl-capture.md)。

## 选择库与版本

在 Linux 上，采集器会搜索发行版常用库路径下的 `libssl.so.3` 或 `libssl.so.1.1` 等文件。应用自带 OpenSSL 时，可用 `--libssl` 指定实际路径。在 Android 上，采集器也会搜索 Conscrypt APEX 和系统库目录。某些 Android 应用自带 TLS 实现，其使用的库可能与系统库不同。[Linux 库查找](https://github.com/gojue/ecapture/blob/v2.12.0/internal/probe/openssl/config_linux.go) · [Android 库查找](https://github.com/gojue/ecapture/blob/v2.12.0/internal/probe/openssl/config_ecandroid.go)

探针按检测到的版本选择字节码布局。v2.12.0 的版本表包含 OpenSSL 1.0.2、1.1.0、1.1.1、3.x 和 4.0 系列的多个补丁版本，以及 BoringSSL 变体。排查布局匹配问题时，需核对具体的补丁版本或 Android 构建。可通过 `--ssl_version` 指定已确认的版本字符串，例如 `openssl 3.0.12`。[版本映射](https://github.com/gojue/ecapture/blob/v2.12.0/internal/probe/openssl/libs.go) · [版本参数](https://github.com/gojue/ecapture/blob/v2.12.0/cli/cmd/tls.go)

## 同一应用的三种采集结果

```bash
sudo ecapture tls --model text --text-source pcapng
sudo ecapture tls --model keylog --keylogfile openssl.keys
sudo ecapture tls --model pcapng --pcapfile openssl.pcapng
```

每次采集选择一条命令。第一条结合网络包和 TLS 密钥还原应用消息，例如跨多个数据包的完整 HTTP 响应。第二条为另行采集的网络包保存 NSS 密钥日志。第三条将包和密钥写入同一份可用 Wireshark 分析的文件。需要网络包的模式会自动选择网卡，本机回环服务请指定 `-i lo`。[输出格式](https://github.com/gojue/ecapture/blob/v2.12.0/docs/event-forward-api.md)

## OpenSSL 和 BoringSSL 的采集路径

`--text-source hook` 通过 `SSL_read` 和 `SSL_write` 提供单次调用的应用数据片段。默认的网络包数据源使用探针采集的 TLS 密钥，由 SDK 重组消息。如果 client random 尚未初始化，OpenSSL 探针会丢弃过早产生的密钥记录，包括 `SSL_clear` 后复用会话的情况。用于丰富事件的连接元数据在探针内部处理。[OpenSSL 修复与迁移记录](https://github.com/gojue/ecapture/blob/v2.12.0/CHANGELOG.md)

部分 Android BoringSSL 构建包含精简调试符号。探针可从压缩符号表中解析 `bssl::ssl_log_secret`，并在实际加载库的可执行段中找到对应的文件偏移量。[BoringSSL 符号解析](https://github.com/gojue/ecapture/blob/v2.12.0/internal/probe/openssl/boringssl_symbol.go)

```mermaid
flowchart LR
    ELF["Android libssl ELF"] --> Section[".gnu_debugdata"]
    Section --> Symbols["解压内部 ELF 符号表"]
    Symbols --> Symbol["查找 ssl_log_secret"]
    Symbol --> Offset["换算为可执行段的文件偏移"]
```

如果启动成功却没有看到事务，先核对库、网卡和建立连接的时机。可用 [Wireshark 对照检查数据包和解密后的 HTTP](../3-capture-modes/3.6-wireshark-decryption-workflows.md)，区分流量选择问题与解密问题。
