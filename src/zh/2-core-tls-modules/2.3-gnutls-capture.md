# GnuTLS 捕获

`gnutls`（别名 `gnu`）面向 Linux 上链接 GnuTLS 的应用。采集器会在常用系统目录中查找 `libgnutls.so.30`。应用使用其他库文件时，通过 `--gnutls /path/to/libgnutls.so.30` 指定实际路径。

## 匹配库的补丁版本

GnuTLS 的握手数据结构布局随版本变化。eCapture 从库文件中识别版本，也可以通过 `--ssl_version 3.8.12` 等参数显式提供已确认的补丁版本。v2.10.0 新增了实测的 GnuTLS 3.8.10–3.8.13 布局。下表列出了 v2.12.0 为各补丁版本选用的布局。

| 补丁版本范围 | 采用的字节码布局 |
| --- | --- |
| 3.6.12 / 3.6.13–3.6.16 | 3.6.12 / 3.6.13 |
| 3.7.0–3.7.2 / 3.7.3–3.7.6 / 3.7.7–3.7.11 | 3.7.0 / 3.7.3 / 3.7.7 |
| 3.8.0–3.8.3 / 3.8.4–3.8.6 / 3.8.7–3.8.9 | 3.7.7 / 3.8.4 / 3.8.7 |
| 3.8.10 / 3.8.11–3.8.13 | 3.8.10 / 3.8.11 |

校验阶段会拒绝不在映射表内的版本。多个补丁版本的 SONAME 可能同为 `libgnutls.so.30`，判断支持情况时须核对具体补丁号。[完整的 GnuTLS 版本映射](https://github.com/gojue/ecapture/blob/v2.12.0/internal/probe/gnutls/config.go) · [版本说明](https://github.com/gojue/ecapture/blob/v2.12.0/CHANGELOG.md)

## 采集及验证

```bash
sudo ecapture gnutls --model text --text-source pcapng
sudo ecapture gnutls --model keylog --keylogfile gnutls.keys
sudo ecapture gnutls --model pcapng --pcapfile gnutls.pcapng
```

选择一条命令启动后，使用 GnuTLS 客户端新建测试连接。文本模式应能找到已知请求路径或响应内容。密钥日志模式可配合同一连接的独立抓包进行解密。pcapng 模式可用 Wireshark 打开原生文件，检查解密后的应用数据。本机客户端和服务端通过回环地址通信时，需指定 `-i lo`。[Wireshark 验证步骤](../3-capture-modes/3.6-wireshark-decryption-workflows.md)

## 握手与记录层事件

网络包文本解密、原生密钥日志和原生 pcapng 使用已选定的布局在 `gnutls_handshake` 处取得密钥。原生 pcapng 把密钥写入解密密钥块（DSB），与数据包保存在同一文件。默认文本路径把这些块送入 SDK，输出解码后的消息。显式指定 `--text-source hook` 时，探针通过 `gnutls_record_recv` 和 `gnutls_record_send` 取得应用读写的数据片段。[GnuTLS 采集实现](https://github.com/gojue/ecapture/blob/v2.12.0/internal/probe/gnutls/gnutls_probe.go)
