# 密钥日志模式 (Keylog)

已有独立的网络抓包时，可选 `--model keylog`（别名 `-m key`）。eCapture 以 NSS Key Log 格式保存目标 TLS 实现产生的会话密钥。v2.12.0 要求通过 `--keylogfile`（`-k`）显式指定**本地文件**。

```bash
sudo ecapture tls --model keylog --keylogfile openssl.keys
sudo ecapture gotls --elfpath ./go-client --model keylog --keylogfile go.keys
sudo ecapture gnutls --model keylog --keylogfile gnutls.keys
```

新建 TLS 连接前，先选择其中一条命令启动，同时开启独立抓包。密钥日志模式本身无需指定网卡。应用使用私有库路径时，可按模块使用 `--libssl` 或 `--gnutls` 指定实际文件。

## 识别和使用密钥日志

每行由标签、连接的 client random 和相应的密钥组成，以空格分隔。TLS 1.2 常用 `CLIENT_RANDOM`，TLS 1.3 使用不同条目区分客户端和服务端的握手密钥、应用流量密钥。下面以占位符表示原生文件中的十六进制数据。

```text
CLIENT_RANDOM <client-random-hex> <master-secret-hex>
CLIENT_HANDSHAKE_TRAFFIC_SECRET <client-random-hex> <secret-hex>
SERVER_TRAFFIC_SECRET_0 <client-random-hex> <secret-hex>
```

密钥日志不含包时间戳、顺序或应用数据。用 Wireshark 打开匹配的网络抓包，在 **Protocols → TLS** 首选项中指定密钥日志文件，查找测试请求特有的内容。命令行验证方法见 [Wireshark 解密工作流](3.6-wireshark-decryption-workflows.md)。密钥日志应采用与解密数据相同的访问控制。[密钥日志格式](https://github.com/gojue/ecapture/blob/v2.12.0/docs/example-outputs.md)

## 转发结果

此模式下，`--output runtime.jsonl` 仅写入运行日志。v2.12.0 的终端会将 NSS 密钥行标为事件。若通过 TCP 或 WebSocket 转发，接收端会收到 v2 `KEYLOG` 事件，按顺序写入 `keylog.data` 字节即可还原 NSS 文件。即使已经设置网络接收端，也必须指定本地 `--keylogfile`。[接收端规范](https://github.com/gojue/ecapture/blob/v2.12.0/docs/event-forward-api.md)
