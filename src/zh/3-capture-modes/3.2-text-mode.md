# 文本模式 (Text)

`--model text` 利用网络包和 TLS 密钥重组应用消息。从 v2.11.0 起，三个核心 TLS 模块默认使用 `pcapng` 文本数据源。这个名称表示**解码器的输入格式**。只有显式指定 `--pcapfile` 才会写出 pcapng 文件。

```bash
sudo ecapture tls --model text --text-source pcapng
sudo ecapture gotls --elfpath ./go-client --model text --text-source pcapng
sudo ecapture gnutls --model text --text-source pcapng
```

## 阅读解码消息

解码器重组 TCP 流，并等待可能晚于数据包到达的密钥。它可以还原完整的 HTTP/1.x、HTTP/2 消息以及受支持的 WebSocket 消息。如果 TLS 后端能提供对应的密钥，也可以解密 QUIC v1/v2 上的 HTTP/3。采集 HTTP/3 时记得包含 UDP 流量。显式使用 `--text-source hook` 则输出每次 TLS 读写调用所见的明文片段。[实时解密说明](https://github.com/gojue/ecapture/blob/v2.12.0/README.md#live-decryption-for-text-output)

终端的每一行都标明它属于事件还是运行日志。HTTP 解码记录包含可用的方向、时间戳、端点和连接标识。在 HTTP/2 或 HTTP/3 中，一条连接可承载多个流，需用流 ID 区分。若能观测到，还会提供 PID、进程名、命令行参数，以及 SNI、ALPN、密码套件等非密钥的握手信息。指定 `--output stdout --output session.jsonl` 时，文件保留 v2 数据结构，其中 `event_payload.text.payload` 是字节字段，在 JSON 中用 base64 编码。[文本输出示例](https://github.com/gojue/ecapture/blob/v2.12.0/docs/example-outputs.md)

## 为应用选择解码方式

以下参数适用于 `--model text --text-source pcapng`。原始字节、增量 HTTP 事件与显式应用协议解析三种方式可以择一使用。

| 参数 | 适用场景 |
| --- | --- |
| `--text-raw` | 查看完成认证的 TLS 字节、带偏移量的 QUIC STREAM 片段或保留边界的 QUIC DATAGRAM 消息。 |
| `--text-http-events` | 在 HTTP 标头或正文片段到达时立即查看，包括 SSE 和 HTTP/2 gRPC。gRPC 载荷保留不依赖 schema 的 Protobuf 字节。 |
| `--text-max-decoded-body N` | 配合 HTTP 增量事件，将每条消息的 gzip 解压上限设为 `N` 字节。取零时保留压缩数据。 |
| `--text-protocol dot`、`doh`、`doq`、`mqtt` 或 `redis` | 显式选择 DNS over TLS、HTTPS 或 QUIC，MQTT 3.1.1，或定长 Redis RESP2/RESP3。 |
| `--text-tls-upgrade` | 跟踪一次 `smtp`、`imap`、`pop3`、`ldap`、`postgres`、`mysql`、`connect` 或 `https-connect` 协商。缺少应用解析器时可用原始字节读取协商后的数据。HTTPS CONNECT 支持一层内部 TLS。 |
| `--text-udp-protocol dtls` | 选择使用 ECDHE-RSA 和 AES-128/256-GCM 的 DTLS 1.2。UDP 默认按 QUIC 处理。 |

下面的命令在回环网卡上采集 Go 服务产生的 gRPC 增量事件。

```bash
sudo ecapture gotls --elfpath ./go-server --model text --text-source pcapng \
  --text-http-events -i lo --output stdout --output grpc.jsonl
```

发起已知 RPC，核对 HTTP/2 流和消息数据。单独的 gRPC 消息需要 `.proto` 定义才能还原具名字段。当前探针尚未提供实时解密 ECH 所需的材料。[解码配置](https://github.com/gojue/ecapture/blob/v2.12.0/internal/config/decrypt.go) · [协议支持范围](https://github.com/gojue/ecapture/blob/v2.12.0/README.md#live-decryption-for-text-output)

## 核对 SDK 收到的数据

添加 `--pcapfile session.pcapng` 可以保留送入 SDK 的字节。还需独立密钥日志时可添加 `--keylogfile session.keys`。两个文件均可选，路径须彼此独立，并与 JSON Lines 输出路径不同。按[内嵌密钥的验证流程](3.6-wireshark-decryption-workflows.md)在 Wireshark 中核对目标请求。单条连接产生的诊断日志仅涉及该连接。如果解密流水线意外终止，采集随之停止，程序返回非零退出状态。[解密与诊断](https://github.com/gojue/ecapture/blob/v2.12.0/docs/agent/output-pipeline.md)
