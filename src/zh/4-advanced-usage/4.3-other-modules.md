# 其他模块

eCapture 还提供 NSPR 读写、交互式 Shell 和 SQL 查询探针。这些模块输出各自的文本事件，不使用三个核心 TLS 模块的 `--model` / `--text-source` 模式组合。Linux 构建包含下列五个模块。Android 构建在 OpenSSL/BoringSSL 和 GoTLS 之外还包含 Bash。[平台与模块矩阵](https://github.com/gojue/ecapture/blob/v2.12.0/docs/agent/architecture.md)

## NSS 与 NSPR

`ecapture nspr`（别名 `nss`）观察应用传入 `PR_Read` 和 `PR_Write` 的数据。探针会校验 NSS 3.x 版本，并挂载到导出这两个 NSPR 函数的库。默认在标准目录查找 `libnspr4.so`，也可以用 `--nspr` 指定库路径。此模块输出 NSPR 读写事件，不提供 TLS 密钥提取或 pcapng 模式。[NSPR 命令](https://github.com/gojue/ecapture/blob/v2.12.0/cli/cmd/nss.go) · [探针实现](https://github.com/gojue/ecapture/blob/v2.12.0/internal/probe/nspr/nspr_probe.go)

## Bash 和 Zsh

| 命令 | 可观察的数据 | 配置 |
| --- | --- | --- |
| `bash` | 通过 Readline 采集交互式 Bash 命令行，还会观察执行与退出相关事件，可将命令完成与状态关联。 | `--bash` 选择可执行文件。若 Readline 在共享库中，须同时提供 `--bash` 和 `--readlineso`。`--errnumber` 会略过指定退出状态的记录，默认值为 128。 |
| `zsh` | 采集 Zsh 行编辑器返回的交互输入，此时命令尚无退出状态。 | `--zsh` 选择可执行文件。CLI 接受 `--errnumber`，但它不影响 Zsh 输出。 |

两种 Shell 探针观察命令的时间点不同。分析命令是否实际完成时，需考虑这种差异。[Bash 命令](https://github.com/gojue/ecapture/blob/v2.12.0/cli/cmd/bash.go) · [Zsh 命令](https://github.com/gojue/ecapture/blob/v2.12.0/cli/cmd/zsh.go)

## MySQL、MariaDB 和 PostgreSQL

`mysqld` 观察由服务端 `dispatch_command` 处理的 SQL。`--mysqld`（`-m`）选择**服务端**程序，默认为 `/usr/sbin/mariadbd`。目标解析取决于服务端版本和符号布局。可用 `--funcname` 指定确切符号，也可用 `--offset` 指定已知的文件偏移。可选的 perf 重排序窗口用于处理来自不同 CPU 的样本顺序。[MySQL/MariaDB 命令](https://github.com/gojue/ecapture/blob/v2.12.0/cli/cmd/mysqld.go) · [版本与符号解析](https://github.com/gojue/ecapture/blob/v2.12.0/internal/probe/mysql/config.go)

`postgres` 观察 PostgreSQL 10+ 服务端通过 `exec_simple_query` 执行的简单查询。`--postgres` 选择**服务端二进制文件**，`--funcname` 可指定首个参数为 SQL 字符串的函数。其默认覆盖范围为简单查询协议，排查缺少的语句时可先核对客户端使用的协议。[PostgreSQL 命令](https://github.com/gojue/ecapture/blob/v2.12.0/cli/cmd/postgres.go) · [模块配置](https://github.com/gojue/ecapture/blob/v2.12.0/internal/probe/postgres/config.go)

v2 输出验收矩阵覆盖 `tls`、`gotls` 和 `gnutls`。在 v2.12.0 中，单独的非核心 Shell 和数据库用例仍有部分检查使用旧输出参数。[测试覆盖范围](https://github.com/gojue/ecapture/blob/v2.12.0/test/e2e/README.md)
