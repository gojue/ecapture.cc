# TLS 故障排查

## 探针无法启动

先运行 `ecapture tls --help` 核对参数，`gotls` 和 `gnutls` 也提供相同的帮助入口。查看帮助无需捕获权限。如果提示无法识别 `--eventaddr`、`--logaddr` 或 `--ecaptureq`，说明仍在使用 v2.12 之前的启动命令。参见[集成与部署](4.2-integration-and-deployment.md)。

| 启动失败的位置 | 检查方法 |
| --- | --- |
| 平台或内核检测 | Linux x86_64 至少需要内核 4.18，arm64 至少需要 5.5，loong64 至少需要 6.6。Android 构建面向 x86_64、arm64。 |
| 字节码选择 | 使用 `--btf 0` 时，只内嵌非 CO-RE 对象的二进制会直接使用该对象。其他构建会先检测内核 BTF，再选用可用的对象。显式指定 CO-RE（`--btf 1`）需要可用的 BTF 和 CO-RE 对象。指定非 CO-RE（`--btf 2`）需要二进制内包含对应对象。 |
| 加载程序或挂载 TC 时权限不足 | 核对采集进程加载 eBPF 和读取 perf 的权限。pcapng 模式和默认的 pcapng 文本源都会挂载 TC 程序，都需要对捕获网卡的网络管理权限。 |
| 找不到库、ELF 文件或符号 | 确认应用实际使用的库。`tls --libssl` 指向 OpenSSL/BoringSSL，`gnutls --gnutls` 指向 GnuTLS，`gotls --elfpath` 指向 Go 应用本身。对于移除了符号表的程序，GoTLS 会尝试从 Go 的符号信息恢复地址。根据报错核对库布局和符号，再决定是否调整编译参数。 |

[环境检测](https://github.com/gojue/ecapture/blob/v2.12.0/cli/cmd/env_detection.go) · [字节码选择逻辑](https://github.com/gojue/ecapture/blob/v2.12.0/internal/probe/bytecode/selector.go) · [GoTLS 符号解析](https://github.com/gojue/ecapture/blob/v2.12.0/internal/probe/gotls/config_symbol.go)

## 探针已启动，但没有解码出请求

1. **确认网卡。** 默认文本源 `--text-source pcapng` 同时依赖网络包与 TLS 密钥。启动日志会给出选中的网卡和原因。省略 `-i` 时，优先选择最低度量值默认路由上的可用以太网接口，然后参考收发字节计数或其他已启用接口。本机回环请求应指定 `-i lo`。容器或 VPN 流量可能经过另一张网卡。
2. **新建测试连接。** 在握手前启动采集器，从正在排查的应用发起一次容易识别的请求。核对 PID 过滤条件以及库或可执行文件路径。解码一条连接需要配对的包和密钥。
3. **检查可选的原始捕获。** 文本模式下指定 `--pcapfile sample.pcapng` 可以保存解码器看到的包和内嵌密钥，然后在 [Wireshark](../3-capture-modes/3.6-wireshark-decryption-workflows.md) 中对照同一次请求。若只有加密数据包，还应检查是否捕获了对应会话的密钥。
4. **核对应用协议。** 自定义二进制协议通常没有可供输出的 HTTP 消息。使用 pcapng 文本源时，`--text-raw` 可查看通过认证的解密字节，`--text-http-events` 可观察仍未结束的 HTTP 响应。需要对比函数调用边界时，可显式选择无需网卡的旧数据源 `--text-source hook`。

SDK 会对不完整或不支持的连接发出限频诊断，其他连接仍可继续。如果实时解码器意外退出，eCapture 会报告错误、清理探针并以非零状态退出。此时应核对进程退出状态与最后一条运行错误。[解密与诊断逻辑](https://github.com/gojue/ecapture/blob/v2.12.0/docs/agent/output-pipeline.md)

## 终端、文件或订阅端缺少预期数据

| 现象 | 原因及处理 |
| --- | --- |
| 添加文件输出后，终端不再显示文本 | 显式目标会替换默认 stdout。使用 `--output stdout --output capture.jsonl` 可同时保留两份输出。 |
| 文件中出现 JSON，或者只有运行日志 | `--output` 文件写入 JSON Lines。keylog、pcapng 模式下该文件仅存运行日志。分别用 `--keylogfile` 或 `--pcapfile` 指定独立的本地原生文件，并核对两个路径的写权限及剩余空间。 |
| WebSocket 客户端连接失败 | 启用 `--stream-listen`，连接配置的路径，协商子协议 `ecapture.v2`。非浏览器客户端也要发送有效的 Origin。[接收端示例](https://github.com/gojue/ecapture/blob/v2.12.0/examples/ecaptureq_client/README.md) |
| 新订阅端无法解密既有连接 | 服务端发送新的段头和后续包、密钥。先订阅，再发起测试连接。配置重载后需重新连接并写入新的接收文件。 |
