## 1. 左栏：选择范围 {#filters}

| 控件 | 选择的内容 |
| --- | --- |
| **全部流量** | 普通记录范围 |
| **已标记** | 当前页面会话中标记的记录 |
| **协议** | 协议类别；HTTP/1、HTTP/2 共用 **HTTP/1 · 2**，HTTP/3 单独列出 |
| **进程** | 归属于所选进程的记录；配对记录可由两侧实际捕获到的任一进程匹配 |
| **目标主机** | 记录中的目标主机值，不会重新进行 DNS 查询 |

进程、协议、主机、类别和搜索词 **共同生效**。例如选择某个进程、HTTP/3，再搜索 `catalog`，只保留同时满足三项条件的记录。协议按钮只展示当前筛选范围里实际存在的类别；按钮暂时消失不等于产品不支持查看该协议。

列表上方的类别按钮进一步缩小范围：

- **异常**：HTTP 状态码大于等于 400、明确的失败/协议错误，以及需要注意的部分捕获。
- **未配对**：尚未关联到最终响应的记录，不是耗时或超时筛选。
- **JSON**：响应 Content-Type 含 `json` 的 HTTP 记录，或载荷文本能解析为 JSON 的非 HTTP 记录。它不是 SQL 查询语言。

搜索框可查找 URL、SQL、Topic、命令、进程信息、Headers 和已捕获内容，在保留数据内做不区分大小写的文本匹配，不会发起新的采集请求。**在 eCaptureQ 中按 Cmd/Ctrl + K** 可聚焦搜索框。

当前条件显示在列表上方。点击条件的 × 只移除该项；点击进程标题旁的 **清除** 只取消进程条件；点击 **清除全部** 取消包括搜索、已标记范围在内的所有条件。清除筛选不删除记录。列表意外为空时，先检查这些条件标签。

## 2. 中栏：读懂一条记录 {#records}

一行代表 **应用消息、已关联的一组消息，或协议事件**，不是一个 TCP 包。eCaptureQ 消费上游交付的消息，不负责 TCP 重组。

| 字段 | 含义 |
| --- | --- |
| 序号 / 星标 | 当前筛选结果中的序号（包含分页偏移），或页面内星标；不是网络包序号 |
| 状态 | 实际观察到的 HTTP 状态码，或下方说明的协议/捕获状态 |
| 类型 | HTTP 方法，如 `GET`；或 `PUBLISH`、Redis 的 `GET`、SQL/QUIC 事件等操作 |
| 摘要 / 目标 | HTTP 路径、SQL 片段、Redis 命令、MQTT Topic、QUIC 事件或原始摘要 |
| 次行信息 | 协议、实时记录的采集模块/来源，以及已记录的主机或端点 |
| 耗时 | 可用的观测耗时；`—` 表示未知，不是零。模拟耗时为虚构值 |
| 大小 | 此记录所表示的捕获内容大小，不是全部线上带宽 |

中栏较窄时会隐藏序号、耗时和大小，给摘要留出空间。需要时通过分隔条加宽；分隔条也支持方向键操作。

**未配对** 表示尚未关联到匹配的最终响应；**截断 / 部分捕获** 表示只有部分内容；**观测** 表示看到了事件，不代表操作成功。Redis 的 **推送**、QUIC 的 **重置** 描述各自的协议事件。HTTP 状态码不是 MySQL 结果码，应继续查看对应协议详情。

未知进程、缺失 PID、缺失主机、`—` 和 **未提供** 都刻意保留未知语义。只有响应的 HTTP 记录会说明请求未捕获；缺少 Host/authority 时保留网络端点，不补造 URL。秒级时间戳不足以计算毫秒级响应耗时。

点击一行按需加载详情，用上下方向键切换记录。实时模式 **每页最多获取 200 条摘要**，完整内容按需读取；列表底部提供上一页/下一页。记录可能在读取列表和详情之间被淘汰，收到提示后刷新列表即可。

## 3. 右栏：检查消息 {#details}

### HTTP 页签与正文表示 {#http}

HTTP 页签顺序为 **请求 → 响应 → 连接**。请求、响应分别展示各自的 Headers 和正文，缺失响应不会用虚构内容补齐。其他协议使用专属页签，例如 SQL 查询、Redis 命令/响应、MQTT 报文、QUIC 流事件，详见 [协议与消息详情](/q/zh/protocols/)。

- **格式化**：尽可能格式化 JSON；HTML 使用隔离的只读预览，禁用脚本和外部资源。
- **原文**：查看当前选择的正文表示，不进行美化；图片正文在能力允许时显示捕获图片。
- **Hex**：以字节形式检查二进制或文本内容。
- **自动换行**：让长行适应正文区域；复制按钮复制当前正文表示或载荷。

压缩 HTTP 正文提供 **解压后** 与 **原始压缩** 切换。这是 HTTP 正文解压，区别于上游 TLS 解密和应用协议解析。支持能力允许时处理 gzip、deflate、br，共享服务提供有界回退。损坏或截断输入、每层 2 MiB 解压输出上限、5 秒处理超时或能力不支持时，会说明原因并保留原始字节。原文、Hex 和正文复制遵循当前选择；导出保留捕获内容，不会用解压结果替换原始内容。

图片 **来自捕获字节**，不会重新请求原始 URL。压缩图片先解压，SVG 仅作为图片展示。不完整或不支持的图片会显示原因，不通过重新访问网络补图。

### 连接、进程与 TLS {#connection}

**连接** 页展示来源、进程名/PID、捕获时的进程命令快照、连接标识、消息方向、传输协议和采集时间。配对记录可展示实际捕获到的两个本机进程，但不能仅凭进程归属判断客户端/服务端角色。命令参数可能截断（最多捕获 256 字节），界面会提示，原始捕获表示保留在导出 JSON 中。

兼容采集器提供数据时，**TLS 握手** 显示版本、密码套件、SNI、客户端/协商 ALPN、密钥交换组、签名算法、**JA3** 和 **JA4**。这些是握手元数据和指纹，不是会话密钥查看器。字段不会从 HTTP Host 或其他连接推测。已发布 eCapture v2.10.0 尚不提供新增的官方进程参数/TLS 字段，详见 [兼容性要求](/q/zh/protocols/#tls)。

### 复制、星标与导出 {#export}

只有捕获到请求和所需 Host/authority 时，才提供 URL 或 cURL 复制。复制不会执行请求。点击详情标题的星标，再通过左栏 **已标记** 找回记录。

实时模式的 **导出当前页 JSON** 导出 **当前页** 满足筛选条件的记录及其详情，不会导出所有分页。模拟模式的 **导出 JSON** 导出当前筛选的样例列表。若导出期间记录已淘汰，会提示错误，应刷新后重试。桌面版使用原生保存对话框，Web 版使用浏览器下载；桌面单次导出上限 64 MiB，剪贴板内容上限 4 MiB。

刷新页面或切换数据模式会清空星标，星标不阻止缓存淘汰。分享前检查导出内容，真实捕获可能含凭据或个人信息。

## 操作练习：查看支付响应 {#practice}

在 **模拟** 模式即可完成，不需要采集器：

1. 点击 **重置模拟数据** 图标恢复内置记录，在左栏选择 **`checkout-api`** 进程。
2. 选择 **HTTP/1 · 2**，列表只保留该进程的 HTTP/1.x、HTTP/2 记录。
3. 搜索 **`payments`**，检查列表上方同时出现进程、协议、搜索三个条件。
4. 选中 **`POST /v1/payments`** 记录；**502** 是虚构样例中的状态。
5. 打开 **响应 → 格式化**，查看示例 JSON 错误和 Headers，再打开 **连接** 查看合成进程/TLS 信息。
6. 点击搜索条件的 ×，再点击进程标题旁的 **清除**，最后 **清除全部** 恢复完整范围。

样例错误内容和耗时用于演示，不是对运行中服务的诊断。随后可按 [快速开始](/q/zh/quick-start/) 连接来源，重复相同流程。

## 刷新、主题与窄窗口 {#display}

**暂停刷新** 只暂停界面记录更新；后台来源继续接收，缓存淘汰仍会发生。恢复后重新获取当前结果。模拟/实时切换也只影响显示，不停止接收。

主题按钮切换明暗模式。语言菜单提供 English 和简体中文，捕获文本保持原值。窄窗口通过筛选开关、详情返回切换视图，而非同时挤入完整三栏。文档网站可以在手机阅读，不代表已经提供受支持的 Android 或 iOS eCaptureQ 客户端。
