# 常见问题

先查看数据源状态与当前筛选条件。事件通道已连接和列表已经有消息，是两项不同的检查。

## 数据源连接失败 {#connection}

确认 eCapture 使用 **`--ecaptureq`** 启动，事件监听仍在运行。填写的是事件端点，不是 HTTP 页面地址或 `--eventaddr`。查看来源的错误/重试日志，检查主机、端口、路由和防火墙规则；若使用了 SSH 隧道，再确认隧道仍然连通。

Web 模式需要从 **Web 服务主机** 检查可达性。来源表单的 `127.0.0.1` 指该主机，不是浏览器电脑；目标应填写可达地址，而非 `0.0.0.0`。`wss` URL 需要真实的 TLS 入口。参见 [数据源连接](/q/zh/data-sources/#addresses)。

## 已连接，却没有记录 {#no-records}

1. 从模拟切换到 **实时**；若暂停刷新，先恢复。
2. 点击列表上方 **清除全部**。
3. 在探针附加成功后，让目标程序产生新流量。
4. 确认模块、库/可执行文件、网卡正确，需要完整消息时使用对应采集模式。
5. 检查来源日志和 eCapture 自身日志。

WebSocket 连接成功只说明通道可用，不代表采集到了目标。附加前或断线期间错过的消息不会回放；有某个协议查看器也不会自动启用上游不支持的采集能力。

## 筛选后列表为空 {#filters}

进程、协议、主机、类别、星标和搜索会组合生效。逐一移除条件标签，点击进程标题旁的清除，或 **清除全部**（包括搜索词）。协议按钮可能因当前范围中没有该类记录而消失。清除筛选会保留捕获数据。

如果选中记录已经被淘汰，刷新列表即可；移除筛选不能找回它。可以用固定的 [模拟练习](/q/zh/interface/#practice) 检查操作流程。

## “未配对”是什么意思？ {#unpaired}

当前记录尚未关联对应消息或最终响应。可能某一侧没有捕获、连接提前关闭、标识不完整，或另一侧已超出保留范围。它 **不能说明服务端仍在执行、已经超时或已经失败**，也不是 POST 特有状态。

关联限制在同一来源、重连代次、连接标识内；HTTP/2、HTTP/3 还需要 Stream ID。迟到响应不能复活已淘汰请求，也不能仅凭列表中两条相邻就推断它们是一组。

## 进程、耗时或 TLS 信息缺失 {#metadata}

缺失值保持未知。旧采集器或某些模式可能缺 PID/命令，时间戳可能没有足够精度计算耗时，TLS 握手也可能未被捕获。PID 0 或 `decryptor` 不是实际应用身份。eCaptureQ 不会从 Web 主机进程或 HTTP Host 补齐这些字段。

已发布 eCapture **v2.10.0** 缺少新的官方进程参数和 TLS 字段，需要这些信息时应使用包含兼容元数据变更的采集器，参见 [协议兼容性](/q/zh/protocols/#tls)。TLS 版本、密码套件、SNI、ALPN、JA3/JA4 是握手元数据，不是会话密钥展示承诺。

## HTTP 正文解压或图片预览失败 {#body}

检查 `Content-Encoding` 及记录是否截断。**原始压缩** 保留捕获字节，**解压后** 是这些字节的展示结果。损坏内容、不支持的算法、每层 2 MiB 解压输出上限、5 秒处理期限都可能阻止解压。界面会说明原因并保留原始表示，必要时可用 Hex 检查。

图片来自捕获字节，绝不重新访问原始 URL，因此缺失部分不会通过网络补齐。HTTP 正文解压不同于 TLS 解密，后者由上游 eCapture 负责。参见 [正文表示](/q/zh/interface/#http)。

## 暂停是否停止采集？ {#pause}

不会。**暂停刷新** 只停止界面记录更新，已配置来源继续在后台接收，记录仍可能被淘汰。恢复后获取当前结果。模拟/实时决定显示的数据集，在模拟模式下来源也可以保持连接。

要停止采集器，应单独管理采集器进程。在 eCaptureQ 登记启动命令，既不会执行，也不会停止它。

## 记录能保留多久？ {#retention}

默认上限为 **65,536 条记录**、**192 MiB 计量记录 JSON**，达到任意一项就淘汰最旧记录。字节数不是整个应用进程的内存（RSS）上限；可通过 `--max-records`、`--max-memory-mib` 调整。

实时每页最多 200 条摘要，详情按需读取，所以记录可能在读取详情或导出前消失。`evicted` 统计容量淘汰的记录，`dropped` 统计 UI 服务拒绝的非法或超大记录；二者都不是内核或采集器丢包计数。星标不保护记录免于淘汰。

## 重启后保留什么？ {#restart}

实时记录和运行日志只在内存中，应用或服务退出即丢失。未指定 `--sources` 的界面新增来源也会丢失。可写来源清单能保存连接设置，但不保存捕获内容，参见 [保存来源配置](/q/zh/data-sources/#save)。

浏览器刷新不等于重启 Web 服务：只要服务继续运行，它的实时缓存仍在，但页面内星标会清空。分别启动的桌面/Web 实例有独立会话和缓存，不会恢复或合并彼此的数据。需要保留的重要记录请及时导出。

## 星标与导出在哪里？ {#export}

点击记录详情标题处的星标，再选择左侧 **已标记**。星标仅存在于当前页面会话，刷新页面或切换数据模式时清空；它既不持久保存记录，也不阻止淘汰。

实时模式 **导出当前页 JSON** 保存本页筛选结果，不是所有结果页；模拟模式 **导出 JSON** 保存当前筛选样例。若提示记录已不可用，刷新后重试。桌面版使用保存对话框（导出上限 64 MiB、剪贴板上限 4 MiB），Web 版使用浏览器下载/剪贴板能力。浏览器不能复制时可导出文件。分享真实数据前先检查敏感内容。

## 为什么下载界面与截图不同？ {#version}

截图展示使用合成数据的 **v1.0.0**。旧 alpha.2 下载使用较早布局和 `ecaptureq-server` 程序名。本文的双语控件、分栏布局和 `ecaptureq-web` 程序以 v1.0.0 为基线；其他版本请核对各自的发布说明。窗口宽度、筛选条件、明暗主题也会影响可见内容，安装与版本范围见 [安装与版本范围](/q/zh/install/#version)。

源码版本字符串或标签不证明二进制已发布，下载以 [官方 Releases](https://github.com/gojue/ecaptureQ/releases) 为准。旧 Tauri 实现的 SQL 过滤、集成启动器和配置格式不是本次重写的兼容性要求。
